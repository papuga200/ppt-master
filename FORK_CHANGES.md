# Fork changes

This is a fork of [hugohe3/ppt-master](https://github.com/hugohe3/ppt-master); upstream's licence and notices are unchanged. Branch `consulting-quality` starts at upstream commit `47ef2b5679305c014672433728d39d99df4ee2ad` (tag `baseline-47ef2b5`). This file is the complete list of local changes, so an upstream update can be reviewed deliberately.

## Purpose

Consulting-quality slide design and a coherent deck, by shortening the path between a visual decision and its visible consequence. PPT Master's Strategist, Design Spec, lock, SVG contract, checker and exporter stay the foundation. There is no intermediate slide representation between the model and the SVG, and no fact-verification subsystem: faithfulness to the supplied material is an instruction to the model.

| `skills/ppt-master/scripts/page_lint.py` | The geometry lint: lays a page out in Chromium and measures every line of text, stroke and shape, with paint order. `CERTAIN` findings (text on text, off-canvas or invisible text, a contract error) must be fixed before a review; `FLAGGED` findings (a line through text, text leaving its shape, a shape over text) go to the reviewer with a 3x crop each, and the reviewer rules `DEFECT` or `ACCEPTABLE`. Deliberately not exhaustive: it is tuned to be right in the great majority of cases and leaves the rest to judgement. Runs inside `page_review.py render`; renders that only fix its findings do not count as revisions. Diagram semantics (F04, all FLAGGED): `ORPHAN_LABEL`, `LOOP_WITHOUT_HEAD`, `CONNECTOR_NO_TARGET`, `UNKEYED_CALLOUT`, `BOUNDARY_CROSSING`, from connectors rebuilt out of the drawn lines and arrowheads; `BAR_WITHOUT_LABEL` accepts a name wrapped just above a short bar. |

Rejected slides never appear on a sheet and return only as labelled counterexamples. |
| `skills/ppt-master/scripts/pptx_parity.py` | Measures the exported deck in Microsoft PowerPoint itself (COM through PowerShell, read-only, invisible, time-bounded, always closed): every text frame's bound box and line count, every paragraph's bullet and automatic number, every native table row's real height and every cell's lines. Compares them with the exporter's plan (the frames and planned row heights in the file) and with the SVG pages (baselines, line counts, typed list numbers, table-cell anchors) and reports per slide `OVERFLOW`, `TEXT_COLLISION`, `ROW_GROWTH`, `TABLE_OVERLAP`, `HEADER_SPLIT`, `LINE_COUNT_DRIFT`, `STRAY_BULLET`, `ACCIDENTAL_BULLET`, `RENUMBERED` and `ALIGNMENT_DRIFT`, certain or flagged, with a box on the 1280 x 720 page and a crop of the PowerPoint render (`IMAGE:` lines). Writes `<deck>.parity.json` and `.parity.md`; `repair_briefs` turns the certain findings into one message per page. The deck runner runs it after every export and sends one bounded repair round (`--no-parity-repair` turns the round off). |
| `skills/ppt-master/scripts/native_table_wrap.py` | F03 cycle 2: predicts, while a page is drawn, where PowerPoint will wrap a native table's cells differently from the browser preview. The exporter's own table conversion gives the column widths, planned row heights, cell margins (PowerPoint's 0.1 in / 0.05 in when none is written) and every run's face, size and weight; each paragraph is broken the way PowerPoint breaks it with the installed font's advance widths, a line is 1.2 x its size, a row the taller of its planned height and its tallest cell. Findings in page_lint's shape: `NATIVE_WORD_SPLIT` (certain: a word wider than its cell's text width), `NATIVE_WRAP_DRIFT` (flagged: more lines than the SVG draws), `NATIVE_ROW_GROWTH` (flagged when the grown table reaches the next shape below, a note when it grows into free space), each with the column width it needs. Calibrated on 34 tables PowerPoint measured: all 1,002 cell paragraphs' line counts and all 241 row heights predicted. `native_parity.py` runs it beside the exporter's parity gate, so `page_lint.py` reports it with every render. |
| `skills/ppt-master/scripts/pptx_text_in_shapes.py` | Runs on the exported .pptx and makes it edit the way a hand-built deck does, without moving anything on the rendered slide (`--verify` compares the PowerPoint renders before and after; the exporter's own file is kept under `exports/floating-text/`, upstream's exporter is untouched). Text: one-line texts that are the lines of one paragraph become one wrapping paragraph; a text box goes into the smallest shape that contains it and is painted beneath it (the shape's own text frame, insets reproducing the position, a lone centred label anchored to the middle); what is left forms heading-and-body blocks that end at a rule, a larger heading or a drawn bullet; typed `1.` `2.` items become automatic numbering in the number's colour; the slide's title becomes its title placeholder. Objects: every object that holds text is named after its first words (Selection Pane), hairlines drawn as thin rectangles become real lines, a straight arrow that runs from the edge of one rectangle to the edge of another becomes a real connector glued to both (verified in PowerPoint: move the box, the arrow follows; multi-bend paths stay drawings), pictures get alt text. Deck: the header, logo, rules, footer and page number that repeat on the content slides move to ONE new slide layout and the page number becomes a field; slides without them (a cover) keep their layout. Built on PowerPoint's measured line model (a single-spaced line is 1.2 x the font size for every font tried; with exact spacing the baseline sits at 80% of the line; paragraph spacing keeps whole points) and on real advance widths from the installed font files. `glue_connectors` also turns exported freeform arrows of one segment, or two or three horizontal and vertical segments, into straight / bentConnector2 / bentConnector3 connectors glued to both boxes (`elbow_connector`); U-turns and longer routes stay drawings. |
| `skills/ppt-master/references/consulting-typesetting.md` | Line spacing by role (title 1.15-1.2, heading 1.2-1.3, body 1.4-1.5 and never under 1.3), paragraph / list-item / block gaps (inside a group always tighter than between groups), padding and measure, what to do when words do not fit (shorten, step down, restructure - never squeeze the lines), lists as native lists with a typed coloured marker, tables as native tables styled per cell.
