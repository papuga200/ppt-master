# Fork changes

This is a fork of [hugohe3/ppt-master](https://github.com/hugohe3/ppt-master); upstream's licence and notices are unchanged. Branch `consulting-quality` starts at upstream commit `47ef2b5679305c014672433728d39d99df4ee2ad` (tag `baseline-47ef2b5`). This file is the complete list of local changes, so an upstream update can be reviewed deliberately.

## Purpose

Consulting-quality slide design and a coherent deck, by shortening the path between a visual decision and its visible consequence. PPT Master's Strategist, Design Spec, lock, SVG contract, checker and exporter stay the foundation. There is no intermediate slide representation between the model and the SVG, and no fact-verification subsystem: faithfulness to the supplied material is an instruction to the model.

## Added

| Path | What it is |
|---|---|
| `skills/ppt-master/workflows/profiles/consulting-quality.md` | The profile: Default Generate plus a per-page render-and-inspect authoring loop, matched reference slides, a deck review, and inspection of the exported PPTX. Explicit intent only. |
| `skills/ppt-master/references/consulting-review.md` | The review language: the four-question page note, symptoms of generated-looking design, what strong architecture / timeline / summary / comparison pages do, the deck review. A way of looking, not a rule set. |
| `skills/ppt-master/scripts/page_review.py` | `render` (numbered backups, revision count, `IMAGE:` line, optional crop), `review` (the independent reviewer: one fresh model call with the render, the §IX record, the review language and the page's references; a defect inventory first, then `VERDICT: PASS | EXECUTION_REPAIR | CONCEPT_REPLAN`), `restore`, `note` (`accepted` is refused without a `PASS` review of the current revision), `contact-sheet`, `status`; keeps the small journal `quality-run.json`. |
| `skills/ppt-master/scripts/page_lint.py` | The geometry lint: lays a page out in Chromium and measures every line of text, stroke and shape, with paint order. `CERTAIN` findings (text on text, off-canvas or invisible text, a contract error) must be fixed before a review; `FLAGGED` findings (a line through text, text leaving its shape, a shape over text) go to the reviewer with a 3x crop each, and the reviewer rules `DEFECT` or `ACCEPTABLE`. Deliberately not exhaustive: it is tuned to be right in the great majority of cases and leaves the rest to judgement. Runs inside `page_review.py render`; renders that only fix its findings do not count as revisions. |
| `skills/ppt-master/scripts/reference_library.py` | A folder-plus-index library of real slides, outside the repository (`PPT_MASTER_REFERENCE_LIBRARY`). `build` renders and indexes a PDF or PPTX one deck at a time (so a user-supplied reference deck enters at run time); `sheet` shows every slide of a form on one contact sheet with ids stamped, so the author looks and picks rather than searches; `label` files a page's form and verdict; `show` delivers a chosen slide full size; `match` keeps the keyword shortlist. Rejected slides never appear on a sheet and return only as labelled counterexamples. |
| `skills/ppt-master/scripts/pptx_text_in_shapes.py` | Runs on the exported .pptx and makes it edit the way a hand-built deck does, without moving anything on the rendered slide (`--verify` compares the PowerPoint renders before and after; the exporter's own file is kept under `exports/floating-text/`, upstream's exporter is untouched). Text: one-line texts that are the lines of one paragraph become one wrapping paragraph; a text box goes into the smallest shape that contains it and is painted beneath it (the shape's own text frame, insets reproducing the position, a lone centred label anchored to the middle); what is left forms heading-and-body blocks that end at a rule, a larger heading or a drawn bullet; typed `1.` `2.` items become automatic numbering in the number's colour; the slide's title becomes its title placeholder. Objects: every object that holds text is named after its first words (Selection Pane), hairlines drawn as thin rectangles become real lines, a straight arrow that runs from the edge of one rectangle to the edge of another becomes a real connector glued to both (verified in PowerPoint: move the box, the arrow follows; multi-bend paths stay drawings), pictures get alt text. Deck: the header, logo, rules, footer and page number that repeat on the content slides move to ONE new slide layout and the page number becomes a field; slides without them (a cover) keep their layout. Built on PowerPoint's measured line model (a single-spaced line is 1.2 x the font size for every font tried; with exact spacing the baseline sits at 80% of the line; paragraph spacing keeps whole points) and on real advance widths from the installed font files. |
| `skills/ppt-master/references/consulting-typesetting.md` | Line spacing by role (title 1.15-1.2, heading 1.2-1.3, body 1.4-1.5 and never under 1.3), paragraph / list-item / block gaps (inside a group always tighter than between groups), padding and measure, what to do when words do not fit (shorten, step down, restructure - never squeeze the lines), lists as native lists with a typed coloured marker, tables as native tables styled per cell. The lint measures the line spacing (`TIGHT_LEADING`). |
| `skills/ppt-master/scripts/pptx_render.py` | Renders the exported PPTX itself (PowerPoint through COM, else LibreOffice + PyMuPDF) to per-slide PNGs and a contact sheet; says so plainly when no renderer exists. |
| `hosts/responses_api/host.py` | A thin tool-execution host for a model behind the OpenAI Responses API: file tools, `edit_file` for local SVG revisions, the skill's scripts, and real image delivery for every `IMAGE:` line. No workflow logic lives here. Production does not depend on any vendor's coding agent. |
| `hosts/responses_api/deck_runner.py` | Authors a planned deck page by page in parallel: one isolated conversation per page over one shared system prompt (page-author brief, contract documents, design system, Narrative, deck digest, lock), a chrome anchor page first, the record's `Author tier` routing each page to a workhorse or a frontier author, a reviewer per tier from another model family than the author, checker repair rounds in the page's own session, escalation of unresolved workhorse pages, a deck review, export (by default even when the repair budget is spent, with the open items written beside the deck; `--strict-export` refuses), a final lint of the pages as shipped, and a cost summary. Before planning, it prepares a source-image catalog for the solution lead and planner; page authors can place selected, inspected assets and cite their origin. |
| `hosts/responses_api/source_assets.py` | Converts supplied decks and documents into source text and embedded-image candidates, collects standalone source images, and renders PowerPoint slide previews when a renderer is present. Its catalog records source paths and slide occurrences and is refreshed against a source-content revision so replaced decks cannot leave stale slide previews in the current candidate list. |
| `hosts/responses_api/planner_examples/story_calibration.md`, `FORK_STORY_PLANNING_DESIGN.md` | Few-shot planning records and the prototype's rationale, evidence and remaining limitations, including how a supplied visual is selected for a page's specific job. |
| `hosts/responses_api/acceptance.py`, `hosts/responses_api/run_report.py`, `FORK_ACCEPTANCE_CHECKLIST.md` | The gate before a run is called ready: what the user approved, item by item, and the script that checks everything a program can check on the plan, the template, the configuration, the journal, the SVGs and the exported deck (including the PowerPoint before/after render of the export pass); and the report of time and cost per step and per model. |
| `hosts/responses_api/evaluate_proposal.py` | Scores a finished deck the way the client's panel would, with a model from another family (Claude Opus 5.5 by default): each of the request's criteria with its weight, logic, consistency with recomputed totals, integrity against the firm's knowledge base, template fidelity and visual quality, from the PowerPoint render and the slide text; it also measures fonts and colours against the base template's theme. |
| `hosts/responses_api/report.py` | Reads a host session and reports calls, wall time, API latency, tokens, cache share, cost, tool mix and outcomes. |
| `skills/ppt-master/scripts/tests/test_consulting_quality_tools.py` | Tests for the journal, the matcher, the library commands, the reviewer gate, the deck runner's parsing and prompts, parallel journal writers, and the lint's rules on plain geometry. |
| `skills/ppt-master/scripts/deck_consistency.py`, `skills/ppt-master/scripts/tests/test_deck_consistency.py` | Deterministic cross-page check (campaign failure family F06) over a project's page SVGs or an exported .pptx: one quantity with two values (`FIGURE_CONFLICT`, certain), one value written two ways (`FORMAT_DRIFT`), name variants (`TERM_DRIFT`, with an optional `## Glossary` in design_spec.md), chrome that differs from the majority of body pages or a folio out of sequence (`CHROME_DRIFT`), and one label keyed by different marker fills (`MARKER_DRIFT`). Writes `.review/consistency.{md,json}`. The deck runner runs it before the deck review (whose reviewer is asked to confirm its findings), sends each certain finding to its page in deck repair, and runs it once more after deck repair for the summary and the `.outstanding.md`. |
